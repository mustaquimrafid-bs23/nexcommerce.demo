# Tailwind CSS v4 Engineering Guide

Comprehensive guide and standard for Tailwind CSS v4 styling, architecture, migration, and component development.

---

## 1. Core Architecture: CSS-First (Zero `tailwind.config.js`)

Tailwind CSS v4 is **purely CSS-first**. 

- **No JavaScript Configuration**: Never create or edit `tailwind.config.js` or `tailwind.config.ts`. Configuration lives directly inside your main stylesheet (e.g. `globals.css` or `index.css`).
- **Single Import Directive**: Replace legacy `@tailwind base; @tailwind components; @tailwind utilities;` with a single entry point:
  ```css
  @import "tailwindcss";
  ```
- **Automatic Content Detection**: Tailwind v4 uses the Rust-powered Oxide engine to scan all source files automatically. You do **not** need to declare `content: [...]` file arrays.
- **Modern Browser Support**: Targets modern CSS standards (CSS variables, cascade layers, modern color formats).

## 2. The 4-Step Theme Architecture for Dark Mode & Design Systems

For robust design systems and dark mode, use this exact 4-step architecture:

### Step 1: Define Raw CSS Variables at Root
Define raw color values and semantic tokens in `:root` and `.dark` (not inside `@theme`):
```css
:root {
  --background: oklch(1 0 0);
  --foreground: oklch(0.145 0 0);
  --primary: oklch(0.205 0 0);
  --primary-foreground: oklch(0.985 0 0);
  --muted: oklch(0.97 0 0);
  --muted-foreground: oklch(0.556 0 0);
  --border: oklch(0.922 0 0);
  --radius: 0.625rem;
}

.dark {
  --background: oklch(0.145 0 0);
  --foreground: oklch(0.985 0 0);
  --primary: oklch(0.985 0 0);
  --primary-foreground: oklch(0.205 0 0);
  --muted: oklch(0.269 0 0);
  --muted-foreground: oklch(0.708 0 0);
  --border: oklch(0.269 0 0);
}
```

### Step 2: Map Variables to Utilities via `@theme inline`
Map your custom CSS properties to Tailwind utilities:
```css
@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  --color-muted: var(--muted);
  --color-muted-foreground: var(--muted-foreground);
  --color-border: var(--border);
  --radius-sm: calc(var(--radius) - 4px);
  --radius-md: calc(var(--radius) - 2px);
  --radius-lg: var(--radius);
}
```

### Step 3: Define Global Theme Tokens with `@theme`
For fixed tokens, fonts, and animation curves that do not toggle by theme:
```css
@theme {
  --font-serif: "Playfair Display", Georgia, serif;
  --font-sans: "Inter", -apple-system, BlinkMacSystemFont, sans-serif;
  
  --color-obsidian-950: #0a0b0d;
  --color-obsidian-900: #12141a;
  --color-amber-gold: #c5a059;

  --ease-luxury: cubic-bezier(0.16, 1, 0.3, 1);
}
```

### Step 4: Use Semantic Utility Classes in Components
Apply classes directly in JSX/TSX:
```tsx
<div className="bg-background text-foreground border border-border rounded-lg p-6">
  <h2 className="text-primary font-serif text-2xl">Editorial Collection</h2>
  <p className="text-muted-foreground mt-2">Curated for timeless elegance.</p>
</div>
```

## 3. Critical v4 Gotchas & Breaking Changes from v3

| Feature | Legacy v3 (DO NOT USE) | Tailwind v4 Standard |
| :--- | :--- | :--- |
| **Arbitrary CSS Variables** | `bg-[--brand-color]` | `bg-(--brand-color)` (Use parentheses) |
| **Important Modifier** | `!bg-red-500` | `bg-red-500!` (Exclamation at end) |
| **Prefix Syntax** | `prefix: 'tw-'` in JS config | `@import "tailwindcss" prefix(tw);` -> `tw:bg-red-500` |
| **Transform Reset** | `transform-none` | `scale-none`, `rotate-none`, `translate-none` |
| **Custom Utilities** | `@layer utilities { ... }` | `@utility my-class { ... }` |
| **Default Border Color** | `gray-200` (#e5e7eb) | `currentColor` |
| **Default Ring Width** | `3px` | `1px` |
| **Stacked Variants Order** | Right-to-left | Left-to-right (`focus:hover:...`) |
| **PostCSS Package** | `tailwindcss` | `@tailwindcss/postcss` |

### Source Scanning Gotcha
Tailwind scans raw text files. **Never** dynamically construct class strings:
```tsx
// ❌ BROKEN: Will NOT be generated by Tailwind v4
const color = "red";
return <div className={`text-${color}-500`} />;

// ✅ CORRECT: Full class strings must exist in code
const colorStyles = {
  red: "text-red-500",
  blue: "text-blue-500",
};
return <div className={colorStyles[color]} />;
```

## 4. Modern v4 Features & Primitives

### Native Container Queries
Zero configuration needed. Add `@container` to the parent and `@sm:`, `@md:`, `@lg:` on children:
```tsx
<div className="@container">
  <div className="flex flex-col @md:flex-row @md:items-center gap-4">
    <img className="w-full @md:w-48 aspect-square object-cover" src="..." />
    <div className="flex-1">...</div>
  </div>
</div>
```

### 3D Transforms & Perspective
Tailwind v4 supports native 3D transforms:
```tsx
<div className="perspective-1000">
  <div className="transform-3d transition-transform duration-500 hover:rotate-y-12 hover:-translate-z-4">
    Card Content
  </div>
</div>
```

### Custom Utility Declarations (`@utility`)
Declare project-specific utilities cleanly in CSS:
```css
@utility text-balance {
  text-wrap: balance;
}

@utility glass-card {
  background: rgba(255, 255, 255, 0.7);
  backdrop-filter: blur(12px);
  border: 1px solid rgba(255, 255, 255, 0.2);
}
```

## 5. Next.js 15+ & React 19 Integration

### PostCSS Configuration (`postcss.config.mjs`)
Always use `@tailwindcss/postcss`:
```javascript
const config = {
  plugins: {
    "@tailwindcss/postcss": {},
  },
};
export default config;
```

### Class Merging Utility (`cn`)
Always use `clsx` and `tailwind-merge` for robust prop and state merging:
```typescript
// lib/utils.ts
import { clsx, type ClassValue } from "clsx";
import { twMerge } from "tailwind-merge";

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs));
}
```

## 6. The Abstraction Ladder (When to Add Custom CSS)

Follow this decision order:
1. **Utility First**: Compose markup directly with existing utilities.
2. **Component Abstraction**: If markup repeats across multiple places, extract into a React/Next.js component (`<Button>`, `<Card>`).
3. **Theme Tokens (`@theme`)**: If a design value (color, spacing, font) repeats and belongs to the design system, add it to `@theme`.
4. **Custom Utility (`@utility`)**: If a specific CSS behavior is needed repeatedly across distinct components and cannot be composed simply, declare a `@utility`.
5. **Direct CSS Module / Style Block**: For complex keyframe timelines or bespoke 3D canvas backgrounds. Use `@reference "tailwindcss";` if accessing theme variables inside a scoped style block.

## 7. Quality Checklist Before Merging

- [ ] Zero `tailwind.config.js` or `tailwind.config.ts` files in the repository.
- [ ] CSS files start with `@import "tailwindcss";`.
- [ ] Arbitrary CSS variables use `bg-(--name)` syntax.
- [ ] Important classes use trailing exclamation mark: `class!`.
- [ ] PostCSS uses `@tailwindcss/postcss`.
- [ ] Conditional classes use `cn(...)` rather than template string concatenation.
- [ ] Dark mode variables update cleanly without CSS cascade leaks.
